# marudesk 0.4.0

AI Chat goes terminal-native. You can now drive the desktop agent from a proper
**Claude Code-style TUI** — streaming markdown, inline tool cards, slash
commands, model and session pickers, Esc interrupt, and in-app approval prompts
— all over a zero-config loopback companion bridge that is always on while the
app is running. Or keep the panel. A new toggle in **Settings → Agent → Chat
surface** lets you choose which surface the chat button opens.

## Highlights

### Claude Code-style chat TUI (`npm run chat`)

A full inline terminal UI, not a line REPL. Run `npm run chat` while the desktop
app is open and you get:

- **Streaming markdown rendering** — bold, italic, inline code, fenced blocks,
  links, with line-accurate diff-commit so finished output never repaints.
- **Live tool cards** — spinner while a tool runs, settled card with result once
  done. Reasoning blocks stream with a dedicated prefix.
- **Sticky composer** — bordered input box pinned to the bottom with a status
  line (model · context window · elapsed timer). `\`+Enter` for a literal
  newline; ↑↓ for history; bracketed-paste support; Korean/CJK wide-char-aware
  cursor math.
- **Slash menu** — type `/` to see completions. All desktop slash commands work
  verbatim (`/review`, `/init`, `/commit`, `/plan`, …). TUI-local additions:
  `/model`, `/sessions`, `/resume`, `/new`, `/approval-mode`, `/status`,
  `/exit`.
- **Model picker** (`/model`) — pulls the live model catalog from the running
  app; pick any connected provider+model, preference persisted to
  `~/.config/marudesk-cli/prefs.json`.
- **Session picker** (`/sessions`, `/resume`) — list and resume saved chat
  sessions without leaving the terminal.
- **Inline approval and question panels** — gated-tool approval requests and
  `ask_user` calls paint as a framed prompt block inside the TUI stream; answer
  from the keyboard with no context switch.
- **Esc interrupt** — graceful mid-turn abort; 2×Ctrl+C exits.
- **`--prompt` / `--line` / piped input** — non-TTY and one-shot paths stay
  fully compatible with the v0.3 REPL interface for scripts and CI.

### Always-on companion bridge (zero config)

The TUI connects over a dedicated **loopback companion** (`127.0.0.1`, ephemeral
port) that the desktop app starts automatically alongside the main remote
bridge. No Remote toggle, no manual token copy. A `cli-bridge.json` handshake
file (mode 0600, userData directory) is the only secret exchange needed — same
Chrome DevToolsActivePort pattern. The companion exposes three extra routes the
TUI uses for catalog and session management (`GET /agent/models`, `GET
/agent/sessions`, `POST /agent/resume-session`); these are absent from the relay
protocol, so the relay stays frozen.

Because the companion is loopback + same-user token, it is treated as desktop
trust: the CLI can respond to gated-tool approval requests directly, with no
extra prompt. The remote bridge keeps its L-1 approval guard unchanged.

### AI Chat as a terminal tab (Settings → Agent → Chat surface)

A new `agent.chatSurface` setting (`panel` | `cli`, default `panel`) routes
every chat-open intent — the titlebar chat button, the activity bar chat icon,
and the one-click console **Fix this** button — to either the existing context
drawer panel or a new **"AI Chat (CLI)"** terminal tab running the TUI. Both
surfaces share the same agent loop, so a conversation started in the panel and
continued in the terminal tab is the same session.

The terminal tab uses the `agent-cli` profile: the desktop spawns the bundled
`chat-cli.mjs` entry (asar-unpacked, resolved via `import.meta.url`) with the
bridge URL and token injected as environment variables so the TUI connects
instantly with no user action.

## Platform notes

- **Windows** — the desktop must be running for `npm run chat` to connect. The
  terminal tab spawns `node chat-cli.mjs` from PATH when available; if Node is
  not on PATH it falls back to `cmd.exe /d /s /c "…"` wrapping (ConPTY requires
  a console-subsystem launcher — the GUI-subsystem `electron.exe` binary emits
  nothing under node-pty even with `ELECTRON_RUN_AS_NODE`).
- **macOS / Linux** — same as Windows except the ConPTY workaround is not
  needed; `ELECTRON_RUN_AS_NODE` with the app binary works directly.

## Install

- **Windows** — download **marudesk Setup 0.4.0.exe** and run it. Updates apply
  in place on the next launch/restart.
- **macOS** — download the `.dmg` for your chip (**arm64** for Apple Silicon,
  **x64** for Intel), open it, and drag marudesk to Applications. The build is
  unsigned, so on first launch right-click the app → **Open** to bypass
  Gatekeeper.
- **Linux** — download the **AppImage** (`chmod +x` then run) or the **.deb**
  (`sudo dpkg -i marudesk_0.4.0_amd64.deb`).
