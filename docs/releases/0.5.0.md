# marudesk 0.5.0

Your phone now drives the **same conversation** your desktop is showing. This
release lands the **mobile ↔ PC workspace bridge**: scope the chat to a PC
workspace, pick the provider/model and reasoning effort per chat, and resume
saved sessions — all routed to the PC that actually runs the agent, with the
phone staying thin. Alongside it, a pane-responsive chat layout, per-thread
model memory, a close-to-tray window lifecycle, and a more forgiving OAuth
sign-in. And for the first time, the mobile client ships as a sideloadable
**Android APK**.

## Highlights

### Mobile ↔ PC workspace bridge + session continuity

Drive the desktop agent from your phone, against the conversation the desktop is
already showing:

- **Shared conversation, scoped to a workspace** — the phone pins a PC workspace
  and streams that workspace's *active* thread (exactly what the desktop
  renders). A turn sent from the phone lands in the conversation the desktop is
  looking at, and vice versa. `snapshot` / `reset` / `resume-session` all carry
  the workspace scope, and the loop still refuses a cross-workspace record.
- **Session continuity** — list and resume a workspace's saved conversations
  from the phone (`GET /agent/sessions?workspace=`,
  `POST /agent/resume-session`); the next snapshot repaints both phone and
  desktop with the resumed transcript. "New chat" is a scoped reset both
  surfaces share.
- **Per-chat provider/model + reasoning effort** — the model sheet is fed by the
  PC's connected providers only; the picked provider/model rides each send, and
  reasoning effort mirrors the desktop dial through a new `set-reasoning-effort`
  command (a PC setting; applies on the next turn).
- **Bridge protocol** — new `set-reasoning-effort` verb and
  `GET /agent/workspaces`; workspace scoping across
  snapshot/reset/events/sessions/resume; a per-workspace event fan-out
  (`subscribeWorkspaceAgentEvents`) so an SSE client pinned to a workspace gets
  exactly that stream; `reasoningEffort` projected into agent state alongside
  approval mode. All bridge transports now share one loop API surface.

The cloud relay path stays frozen (its protocol does not carry the catalog
routes), so in relay mode the pickers hide and the chat stays global-scope — the
new continuity rides the direct LAN/pairing path.

### Chat UX

- **Pane-responsive layout** — the Mission Control aside, inline plan, and
  session rail now key off the *pane* width via container queries
  (`@[64rem]` / `@[56rem]`) instead of the viewport, so split views and divider
  drags actually reflow. The aside is collapsible (persisted) with a reopen
  chip.
- **Per-thread model pin** — each thread remembers its own model. The composer
  chip, usage gauge, and reasoning dial follow the active thread, and resuming a
  session re-pins its last-used model.

### Window lifecycle

- **Close-to-tray** — a new **Settings → Window** option (default: minimize to
  tray) keeps the app resident on close, backed by a tray icon. Set
  `MARUDESK_DISABLE_TRAY` to opt out.
- **`Ctrl+W` no longer quits the app** — dropped Electron's default application
  menu on Windows/Linux, whose `Ctrl+W` "Close Window" accelerator quit the
  entire app whenever no tab handler consumed the key (no tabs open, or focus in
  a text field).

### OAuth robustness

- Sign-in now detects whether the OS browser actually opened. The connect card
  adds **copy-URL** and **open-in-app-browser** fallbacks and shows a banner when
  the handoff fails, so a provider login can't silently stall.

### Agent + tools

- **Removed the agent step-limit stop** — longer multi-step turns run to
  completion instead of halting early.
- **Thread-isolation fix** for concurrent conversations, plus developer
  diagnostics.
- `list_files` footers count glob matches and say how to narrow;
  `eval_js` / `web_search` / `list_files` descriptions sharpened; `context:sync`
  skips the IPC when the mirrored payload is unchanged; `open_external` surfaces
  failures.

## Mobile (Android) — new

A sideloadable **Android APK** of the thin client ships with this release. It is
an **unsigned debug build**: download `marudesk-mobile-0.5.0-debug.apk`, allow
"install unknown apps" for your browser/file manager, and install it. The phone
connects to your PC over the direct LAN/pairing path (scan or paste the host's
QR payload), then renders and steers the PC-owned conversation. It never runs
the model or tools itself.

> The APK is unsigned (no Play Store distribution yet), so Android will warn on
> install — that is expected for a sideloaded debug build.

## Install

- **Windows** — download **marudesk Setup 0.5.0.exe** and run it. Updates apply
  in place on the next launch/restart.
- **macOS** — download the `.dmg` for your chip (**arm64** for Apple Silicon,
  **x64** for Intel), open it, and drag marudesk to Applications. The build is
  unsigned, so on first launch right-click the app → **Open** to bypass
  Gatekeeper.
- **Linux** — download the **AppImage** (`chmod +x` then run) or the **.deb**
  (`sudo dpkg -i marudesk_0.5.0_amd64.deb`).
- **Android** — download **marudesk-mobile-0.5.0-debug.apk** and sideload it
  (unsigned debug build).
